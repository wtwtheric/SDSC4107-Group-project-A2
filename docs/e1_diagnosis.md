## 3. 已修掉的三个 bug（都有硬证据）

### 3.1 BatchNorm 在递归下评估失稳 → 改 LayerNorm
- 现象：eval 时 max|δ1| = 8.04（应 ~0.5），price 漂到 3.6 / 5.49 / 27.3 / 4566.6。
- 根因：训练用 batch 统计、评估用 running stats，而 δ(k-1) 是递归反馈，误差沿 30 步复利放大。
- 消融：LN max|δ|=1.49、price 2.61；BN max|δ|=8.04、price 3.47。
- 处理：policy.norm = layer（论文用 BN，记为 documented deviation）。

### 3.2 δ2 的量级 ~1e2 学不动 → 输出重参数化
- 现象：3000 iter 时 δ2 ≈ 0.1，正确量级是 360–520。
- 根因：Adam 的步长上限是 lr=0.005，权重长到 O(100) 需要 1e4 步以上。
- 处理：out_scale=100（δ2 = 100·δ̂2，经济上等价），1000 iter 内 δ2 到 165。
- 附带修复：递归反馈改喂 δ(k-1)/out_scale，否则 500 量级的数直接进第一层，方差腿发散。

### 3.3 方差互换在离散化下不是鞅 → 网络「套利」（最关键）
- 现象：20k iter 时 price **1.6049 < q=1.6918**。而 CVaR_0.5(L) >= E[L] = q 是无套利的必然，
  所以这个「好结果」只能是假的。
- 根因：∫V ds 用左矩形累加时，E[ΔI | V_j] = V_j·Δ - (V_j-b)·α·Δ²/2 + O(Δ³)，
  偏差与 V 相关；δ2 取负值时系统性获利（100k 路径实测 E[S2_T]=0.0032712 vs S2_0=0.0032877，-0.5%）。
- 处理：每步用 CIR 精确转移的条件期望 a_j=(V_j-b)(1-e^{-αΔ})/α + bΔ（QE-M 匹配该一阶矩），
  使 S2_k = I_k + L(t_k,V_k) 严格为鞅。
- 验证：100k 路径 E[S2_T]/S2_0 - 1 = +0.07%（se 0.49%）；训练后 E[L]=1.6894、q=1.6918（差 0.14%）。
- 影响：修复前所有 price < 1.69 的「好结果」全部作废；修复后 price 回到真实水平 2.77。

## 4. 还没解决的部分：最后 0.8 的差距

已排除：
- **不是特征信息不足**。三种输入各跑 6k iter：[log S, t, S2/S2_0] → 3.17，
  [log S, t, v/b] → 3.31，两者都喂 → 3.21。信息够（解析 δ 只用 (S,v) 就到 1.94）。
- **不是量级 / 激活问题**：同一网络能拟合出 mean δ1 ≈ 0.5，量级对。

剩下最可能的两个原因：
1. **CVaR 的分位数梯度噪声**：batch 256 时「最差 50%」的样本集合每步都在变，梯度方差大，
   停在 2.8 附近的极限环（与锯齿轨迹一致）。配方：batch 1024 + cosine lr（5e-3 → 5e-4）。
2. **需要更多步**：论文未给迭代数；若需 1e5 步，CPU 上单 seed 约 50 min。

Plan B（若仍不收敛）：用解析 δ 做 300 步监督热启动，再切 CVaR 20k iter。
代价：Fig 3 的 δ 面对比不再独立，需在 docs/method_replication.md 记一条 deviation。

## 6. 定稿（2026-11-14 补记；第 4 节的两个猜测都被实验推翻）

8 个配方并行跑（`scripts/sweep_recipes.py`，8 进程 × 1 线程，固定 50k eval 集，20 min 跑完）：

| 配方 | price | 备注 |
|---|---|---|
| b1024 + cosine 30k + out_scale `[1,100]` | **1.9424** | 定稿 |
| b1024 + cosine 30k + out_scale `100` | 2.0117 | 只差分腿重参数化 |
| 纯监督拟合解析 δ，3k 步 | 2.0161 | 结构可达性诊断 |
| 监督热启 800 + CVaR 20k | 2.0205 | Plan B |
| b4096 + cosine 12k | 2.0282 | 同等路径预算 |
| b8192 + cosine 6k | 2.0861 | batch 再大无益 |
| b256 + cosine 30k | 2.1198 | 旧 batch，靠 cosine 救回 |
| b1024 + 恒定 lr 30k | 2.2101 | cosine 缺失的代价 |
| 解析 δ 基准（100k 路径） | 1.9353 | 靶子 |

**真正的根因是梯度尺度失衡，不是分位数噪声。** 两腿 `out_scale` 都取 100 时，δ̂1 必须
压到 ~0.007；而 ∂L/∂δ̂1 = ∂L/∂δ1 × 100，标的腿那个信噪比低的 CVaR 分位数梯度被放大
100 倍灌进共享主干，把方差腿的梯度淹掉。证据：第 2500 iter 时 δ2 均值 **30.7**（两腿
都 100）vs **361.1**（分腿），benchmark 534.4。分腿是纯重参数化（δ = out_scale ⊙ δ̂），
函数集合完全相同，**不算 deviation**。

cosine 是第二重要：同 b1024/30k，恒定 lr 2.2101 → cosine 2.0117。batch 256→1024 值 0.1；
batch 8192 反而变差（每步路径多但步数少，学不动 30 步的时间结构）。

**结构可达性**：只做监督回归、完全不碰 CVaR，3000 步就拿到 price 2.0161、δ1 RMSE 0.065、
δ2 相对误差中位数 0.071。之前 2.77 的结果里没有任何「容量不够」的成分，这条诊断 4 分钟可跑。
