# E2/E3 paper-fidelity control experiment

Status: prepared; full GPU runs not yet executed.

## Goal

E2 core (Figures 6-7) reproduces the qualitative risk-aversion trade-off but the
alpha=.99 price/tail statistics are materially below the paper. E3 (Figure 5)
preserves the recurrent-better-than-simpler direction but the price gap is much
smaller than the paper. This experiment isolates two implementation differences
before any broad hyperparameter retuning:

1. Heston path simulator / variance-swap discretization.
2. Network information set.

The validated A2 baseline remains unchanged on `exp/a2-seed0-batch`.

## Paper reference points

Section 5.2.2 states that paths are generated by exact sampling from the CIR
transition density followed by the simplified Broadie-Kaya scheme. Its footnote
describes this as replacing V in the stock SDE by a piecewise-constant process
and replacing the variance integral in equation (31) by a sum.

The same section chooses network input

    I_k = (log(S^1_k), V_k)

while noting that V_k could alternatively be replaced by S^2_k.

The paper reports approximately:

- E2: p_0.50 = 1.94, p_0.99 = 3.49.
- Figure 7 realized excess-loss CVaR:
  - 0.50-policy: CVaR50 0.2531, CVaR99 2.3631.
  - 0.99-policy: CVaR50 0.5270, CVaR99 1.8034.
- E3: recurrent price 5.5137, simpler price 6.7446, gap 1.2309.

## 2x2 design

The existing baseline completes one cell, so only three new seed-0 arms are
required:

| Simulator | Input | Arm |
|---|---|---|
| QE-M baseline | current `[log(S/S0), t/T, S2/S2_0]` | existing baseline |
| paper-style exact-CIR + simplified BK | current input | `simulator_only` |
| QE-M baseline | paper `[log(S), V]` | `paper_input_only` |
| paper-style exact-CIR + simplified BK | paper input | `simulator_plus_paper_input` |

All three new arms keep the current stabilized optimization recipe fixed:
LayerNorm, hidden=17, out_scale=[1,100], batch=1024, 30,000 iterations,
Adam, cosine learning-rate schedule 0.005 -> 0.0005. Therefore any change can
be attributed to simulator/input effects rather than simultaneous optimizer
retuning.

## Paper-style simulator implementation

`simulator=paper_sbk`:

1. Samples every CIR endpoint exactly from its non-central chi-square transition,
   using the Poisson-mixture representation.
2. Approximates integrated variance on each daily interval by `V_k * dt`.
3. Updates log spot using the Heston conditional identity with the exact
   variance endpoint and the approximate integrated variance.
4. Constructs S2 from the accumulated left-point variance sum plus the analytic
   continuation value L(t,V).

This implements the *simplified* Broadie-Kaya description stated in the paper.
It is not the full exact Broadie-Kaya integrated-variance inversion algorithm.

Before training, `scripts.audit_e2e3_simulators` compares QE-M and paper_sbk on
200k paths and records terminal spot/payoff tails, V_15 boundary behaviour,
variance-swap drift and the analytic q reference.

## One-command run

Each arm runs E2 seed 0, a chunked 1M-path E2 evaluation and Figures 6-7, then
E3 seed 0 including its independent 1M calibration/OOS evaluation and Figure 5.

```bash
python -m scripts.run_e2e3_fidelity_control \
  --variant simulator_only \
  --device cuda
```

Other arms:

```bash
python -m scripts.run_e2e3_fidelity_control \
  --variant paper_input_only \
  --device cuda

python -m scripts.run_e2e3_fidelity_control \
  --variant simulator_plus_paper_input \
  --device cuda
```

Use `--resume` after interruption. The simulator audit runs automatically only
for `simulator_only`; use `--skip-audit` to omit it.

Outputs are isolated under:

    results/e2e3_fidelity/<variant>/

Each arm writes `variant_summary.json` with the main E2/E3 metrics and paper
reference values.

## Recommended execution

Use three separate GPUs / instances in parallel, one arm per GPU. Within each
GPU keep E2 and E3 sequential. This avoids GPU contention while preserving a
single provenance chain for each experimental arm.

Do not run all three arms serially on one GPU unless cost constraints require
it. Do not change batch size, normalization, learning-rate schedule, hidden
size, simulator parameters or seeds between arms.

## Interpretation

This is a controlled diagnosis, not a search for the visually closest plot.

- If `simulator_only` moves both E2 alpha=.99 and E3 strongly toward the paper,
  simulator/discretization is the main contributor.
- If `paper_input_only` mainly enlarges the E3 recurrent-vs-simpler gap, the
  current S2-based information set is making the simpler policy unusually
  informative.
- If only `simulator_plus_paper_input` improves materially, the discrepancy is
  an interaction between state distribution and information set.
- If none of the three arms materially improves paper agreement, freeze the
  simulator/input explanation as insufficient and only then test the remaining
  training-recipe differences (BatchNorm, batch=256, constant lr=.005).

No arm should replace the baseline merely because a plotted histogram looks
closer. Quantitative decisions should use 1M-path prices, tail CVaRs and E3
price gaps together with the histogram shape.
